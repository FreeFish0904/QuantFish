# Contributing to QuantFish

Thanks for taking a look. QuantFish is a self-contained A-share factor
research and backtesting platform: a FastAPI backend owns the engine, the
scoring pipeline and the data releases, while a React frontend renders the
student, leaderboard and admin experiences.

## Prerequisites

- Python **3.12+** (CI runs 3.12 and 3.13)
- Node.js **20+** and npm
- Docker only if you want the one-command demo

## Local setup

```bash
git clone https://github.com/FreeFish0904/QuantFish.git
cd quantfish

# Backend: editable install with dev extras
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './backend[dev]'

# Frontend
npm --prefix frontend install
```

Optionally copy `.env.example` to `.env` and fill in the admin credentials.
`scripts/start-quantfish.sh --mode dev` generates throw-away credentials for
you if they are missing.

## Running things

| Task | Command |
| --- | --- |
| Backend tests | `python -m pytest backend/tests -q` |
| Backend coverage | `python -m pytest backend/tests -q --cov=quantfish --cov-report=term-missing` |
| Backend lint | `python -m ruff check backend` |
| Frontend tests | `npm --prefix frontend test -- --run` |
| Type-check + build | `npm --prefix frontend run build` |
| Dev servers (API + Vite) | `scripts/start-quantfish.sh --mode dev` |
| Production-style single port | `scripts/start-quantfish.sh --mode prod --port 8010` |
| Generate the synthetic dataset | `python scripts/gen_sample_dataset.py` |
| Docker demo | `docker compose -f deploy/docker-compose.yml up --build` |
| Static, backend-free demo | `VITE_DEMO_MODE=true npm --prefix frontend run build` |

Run everything from the repository root: several tests and scripts resolve
`config/platform.yaml`, `frontend/dist` and `runs/web_platform` relative to it.

## Repository layout

```text
backend/src/quantfish/   Python package (engine, API, CLI entry points)
backend/tests/           pytest suite
frontend/                React 19 + Vite app
config/                  platform.yaml (single source of truth for settings)
docs/                    architecture, guides and the student handbook
examples/                runnable strategies
scripts/                 developer and operations scripts
deploy/                  Dockerfile and docker-compose for the demo
data/                    placeholder for generated datasets (git-ignored)
```

## Conventions

- **Tests first.** Every behavioural change should come with a pytest or
  vitest case. `backend/tests/test_project_naming.py` guards the branding and
  package layout, so keep module paths consistent with `quantfish`.
- **Lint before pushing.** `python -m ruff check backend` must be clean; CI runs
  it and fails the build otherwise. Rules live in `backend/pyproject.toml`
  (`[tool.ruff]`). `E501` is deliberately off for now so the gate stays about
  behaviour rather than reflowing files; `ruff format` is a separate, opt-in
  change.
- **Config over constants.** Tunables belong in `config/platform.yaml` and are
  validated by `quantfish.platform_config`. Avoid duplicate defaults in code.
- **Types at the boundary.** API contracts come from the FastAPI models. After
  touching a route or response model, regenerate the frontend types with
  `npm --prefix frontend run api-types` and commit the result: CI re-runs the
  same command and fails when the committed types drift.
- **No secrets in git.** `.env` is ignored; never commit real admin passwords or
  session secrets.
- **Forking?** `scripts/set-repo-owner.sh <owner> [repo]` re-points the README
  badges, clone URLs, Pages link and the landing page CTA in one step.

## Pull requests

1. Create a topic branch (`feat/…`, `fix/…`, `docs/…`).
2. Keep commits focused; the history is meant to be readable.
3. Make sure `python -m ruff check backend`,
   `python -m pytest backend/tests -q` and
   `npm --prefix frontend test -- --run && npm --prefix frontend run build`
   pass locally.
4. Describe the user-visible change and any trade-offs in the PR body.

## Data

The real market dataset is **not** part of this repository. Development and CI
use a small synthetic dataset generated by `scripts/gen_sample_dataset.py`,
which follows the same release contract (`data_catalog.json` plus
`stock/`, `market/`, `factor_benchmark/` and `basic/` CSV/parquet files).
