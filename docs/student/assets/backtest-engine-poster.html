回测引擎揭秘

学生策略从上传到成绩单的完整一生
一句话心智模型

学生负责打分 score

平台负责仓位、成交、指标

把 strategy.py 当成一张菜谱交给后厨

平台采购数据、控制火候、模拟成交、扣掉成本，最后端出 summary.csv 和图表。

1

上传 strategy.py

网页端提交策略文件，并选择 learning 或 hidden_test 数据轨道。

入口是 POST /api/submissions；文件会被保存成一次提交任务。
2

校验、入队、隔离执行

平台校验队伍密码，创建任务记录，再由调度器交给独立 Worker。

routes.py → service.py → dispatcher.py → runners.py → score_worker.py
3

逐日调用 generate_signals

每个交易日，平台问一次：今天每只股票应该打几分？

data 只能看到当前交易日及以前；未来数据会触发保护。
4

学生返回 score

返回 Series，或包含 code / score 两列的 DataFrame；NaN 表示没有信号。

学生只能返回分数，不能直接告诉平台“买多少权重”。
5

平台把分数变成权重

longshort 先去均值再归一化；longonly 先把负分截断成 0。

top_k 会先筛股票，再归一化；group_count 只影响分组图。
6

VWAP 成交，Close 结算

昨天收盘后决定信号，今天按 front_vwap 成交，今天收盘按 front_close 结算。

日收益 = 隔夜段 close→VWAP + 日内段 VWAP→close - 交易成本。
7

扣成本，处理交易限制

手续费和滑点按换手率扣；涨跌停、流动性、不可交易状态会影响成交。

涨停不买，跌停不卖；超过流动性上限的仓位变化会被截断。
8

生成成绩单与图表数据

平台输出收益、夏普、最大回撤、换手率、敞口、分组收益和诊断文件。

summary.csv、graph_data.json、Parquet 文件、diagnostics.json

1. score → weight

longshort：score - mean(score)

longonly：max(score, 0)

学生不能直接返回权重

2. price → return

front_vwap 是执行价

front_close 是结算价

隔夜段 + 日内段 - 成本

3. rule → realistic

交易成本按换手率扣

涨跌停、流动性会截断

不可交易状态会跳过

Learning 与 Hidden

同一套引擎，同一套评分规则。

区别只是数据目录和时间窗口。

Learning练习、调试、学生可见
Hidden排行、不可见、正式评分

模块链路速查

routes.py → service.py → dispatcher.py
→ runners.py → score_worker.py
→ strategy_execution.py
→ backtest runner/simulator → report_dir

调试时的顺序

先看 generate_signals 返回的 score，再看平台如何归一化成 weight，最后再追 VWAP / close / 成本限制 / 指标。
